## AppBDS Code Structure

```
code/appbds/
├── static_analysis/          # Static analysis tools
├── preprocessing/           # Data preparation and UCG construction
└── main/                   # Core AppBDS framework implementation
```

## Architecture

The AppBDS framework operates in three main phases:

1. **Phase I: Multi-source Data Acquisition and Preparation**
   - Construct UI-Fused Call Graphs (UCG) from APK files
   - Extract permission propositions from privacy policies
   - Build Permission-related Proposition Knowledge Base (PP-KB)

2. **Phase II: Privacy-Relevant Node Filter and Summarization**
   - Identify privacy-relevant nodes using six distinct patterns
   - Generate specialized subgraphs for different analysis perspectives
   - Create LLM-based node summaries

3. **Phase III: Permission Description Synthesis**
   - Execute parallel analysis across three specialized branches
   - Integrate results through multi-round aggregation
   - Generate final permission usage descriptions

## Static Analysis (`static_analysis/`)

### Overview
Constructs Inter-Component Call Graphs (ICCG) from Android APK files using static analysis techniques, providing the foundational call graph structure for AppBDS analysis.

### Core Components

#### IC3 Integration (`ic3/`)
**Provides inter-component communication analysis**

Analyzes Intent-based communications between app components to identify target components for startActivity calls. Processes IC3 analysis results to enhance call graph connectivity with inter-component relationships.

#### APK Call Graph Builder (`APKCallGraph/`)
**Generates comprehensive call graphs with method body information**

Uses Soot and FlowDroid frameworks to build static call graphs containing method signatures and decompiled Jimple bodies. Handles Android-specific implicit calling relationships including multi-threading, event-driven patterns, and inter-component communications. Extracts Activity-to-layout mappings and exports results in DOT format for downstream processing.

## Preprocessing Pipeline (`preprocessing/`)

### Data Preparation Components

#### Call Graph Post-processor (`apkcallgraph_postprocessing.py`)
**Converts DOT format call graphs to structured JSON**

- Parses DOT files generated by static analysis tools (Soot, FlowDroid)
- Extracts method signatures, node IDs, and method bodies
- Provides standardized JSON input for downstream analysis

#### Resource Analyzer (`CG_node_info_retrieval.py`)
**Extracts and analyzes Android app resources for UCG construction**

- **Resource Parsing**: Processes public.xml, strings.xml, and layout files
- **Code-Resource Linking**: Identifies resource references in call graph nodes
- **UCG Building**: Fuses static call graphs with UI context information
- **Privacy Filtering**: Filters nodes relevant to permission usage analysis

#### Activity Information Extractor (`window_info_retrieval_publicxml.py`)
**Extracts comprehensive Activity-level information**

- **Manifest Analysis**: Parses AndroidManifest.xml for Activity declarations
- **Resource Association**: Links Activities to related UI layouts and resources
- **Call Graph Matching**: Identifies Activity-specific method nodes
- **Dependency Mapping**: Builds complete resource dependency graphs

#### Call Graph Data Enricher (`merge_json_ICCG.py`)
**Integrates multi-source data into unified call graph structure**

- **Data Fusion**: Combines call graph nodes, Activity info, and UI resources
- **Signature Matching**: Links code implementation to UI contexts via method signatures
- **Information Injection**: Adds GUI and resource information to call graph nodes
- **Context Enhancement**: Creates semantically rich input for LLM analysis

### Analysis Integration Components

#### Activity Analyzer (`UCG_activity_LLM_summarize.py`)
**Generates LLM-driven Activity functionality descriptions**

- **Multi-source Integration**: Combines code, UI layouts, strings, and manifest data
- **LLM Analysis**: Uses GPT-4 to analyze Activity functionality and permission usage
- **Dual Summarization**: Produces both detailed analysis and concise summaries
- **Result Injection**: Integrates generated descriptions back into call graph nodes

#### UCG Summary Integration (`merge_summary_UCG.py`)
**Incorporates LLM-generated Activity summaries into UCG structure**

- **Summary Integration**: Adds Activity analysis results to call graph nodes
- **Node Mapping**: Updates UCG nodes with Activity functionality descriptions
- **Batch Processing**: Handles multiple Activity analysis results
- **Context Preservation**: Maintains Activity-to-code-node relationships

### Knowledge Base Construction

#### PP-KB Builder (`PP_KB_construct.py`)
**Constructs Permission-related Proposition Knowledge Base**

- **Two-Stage Pipeline**:
  1. **Proposition Extraction**: Generates permission usage propositions from privacy policies
  2. **External Validation**: Uses web search to verify and enrich propositions
- **Multi-source Synthesis**: Combines policy text, web research, and technical documentation
- **Quality Assurance**: Cross-validates propositions against real app functionality

## Main Framework (`main/`)

### Core Architecture

The main framework implements the complete AppBDS pipeline through coordinated modules:

- **Multi-source Integration**: Combines call graphs, privacy policies, and similar app information
- **Parallel Analysis**: Three-branch analysis architecture (Permission-Focused, Policy-Proposition, Similar-App-Inspired)
- **LLM Description Generation**: Coordinates multiple LLM agents for analysis and synthesis

### Core Components

#### Main Controller (`main_func.py`)
**Primary orchestrator for the complete AppBDS pipeline**

- **Batch Processing**: Manages large-scale app datasets with progress tracking and error recovery
- **Three-Phase Coordination**: Executes data preparation → node filtering → description synthesis
- **Subgraph Management**: Constructs and analyzes three types of specialized subgraphs
- **LLM Integration**: Coordinates GPT-4 and Claude models with fallback mechanisms

#### Privacy Policy Processor (`pp_utils.py`)
**Handles privacy policy analysis and proposition inference**

- **Policy Segmentation**: Extracts permission-specific text segments from privacy policies
- **Proposition Generation**: Uses LLM to create structured permission usage propositions
- **PP-KB Querying**: Retrieves similar app information based on proposition similarity
- **Multi-round Analysis**: Supports conversational privacy policy refinement

#### Call Graph Analyzer (`cg_utils.py`)
**Implements privacy-relevant node filtering and subgraph construction**

- **Six-Pattern Filtering**: Identifies nodes using UI Entry Points, Semantic-Rich, SDK, Permission Access, Proposition-Relevant, and Similar-App-Relevant patterns
- **Embedding-based Matching**: Uses cosine similarity for large-scale node filtering
- **Subgraph Construction**: Builds three specialized subgraphs preserving call relationships
- **Node Summarization**: Generates tailored summaries for different node types

#### Description Generator (`des_gen_utils.py`)
**Synthesizes final permission descriptions through parallel analysis**

- **Three-Branch Analysis**:
  - Branch 1: Permission-focused functionality analysis
  - Branch 2: Policy proposition validation against code evidence
  - Branch 3: Similar-app-inspired feature discovery
- **Two-Round Aggregation**: Integrates findings and generates user-facing descriptions
- **Output Processing**: Handles structured parsing and app identifier filtering

#### Utility Parser (`parse.py`)
**Provides foundational data processing utilities**
